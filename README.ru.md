# Amby Notes: свой сервер синхронизации

[English version](README.md)

Здесь всё, что нужно, чтобы запустить **сервер синхронизации** для [Amby Notes](https://github.com/MrDarkOm/amby-notes) на своём компьютере: файл Docker Compose с готовым образом, настройка Caddy, который сам получает HTTPS-сертификат, и эта инструкция. Кода сервера здесь нет: он лежит в [`amby-notes/sync/`](https://github.com/MrDarkOm/amby-notes/tree/main/sync), а образ `ghcr.io/mrdarkom/ambynotes-sync` собирается из него.

## Что сервер видит и чего не видит

Ваши устройства шифруют всё до отправки. Сервер хранит заметки **в зашифрованном виде** и ничего не может прочитать: ключи до него не доходят. Он **не может прочитать**:

- текст заметок и вложений,
- названия файлов и папок и структуру папок,
- названия ваших устройств и хранилищ,
- ваш пароль, код восстановления и любой ключ.

Он **видит** (этого не скрыть): имена пользователей, сколько у вас файлов и примерно какого размера, когда они менялись, каким устройством, и с каких IP-адресов приходят запросы.

Раз сервер не может прочитать данные, он не может их и восстановить: если вы потеряете и пароль, и код восстановления, данные на сервере не вернёт никто. Файлы на ваших устройствах при этом остаются как были.

## Что нужно

- Компьютер с [Docker](https://docs.docker.com/engine/install/) и плагином Compose (`docker compose`).
- DNS-имя (например, `sync.example.org`), указывающее на этот компьютер.
- Открытые из интернета порты **80 и 443**: через них Caddy получает и продлевает HTTPS-сертификат.

## Быстрый старт

```bash
git clone https://github.com/MrDarkOm/AmbyNotes-SelfHost
cd AmbyNotes-SelfHost/sync
cp .env.example .env
```

Откройте `.env` и впишите в `AMBY_SYNC_DOMAIN` своё DNS-имя. Затем:

```bash
docker compose up -d
curl https://sync.example.org/v1/info    # должен ответить коротким JSON
```

В приложении укажите адрес сервера `https://sync.example.org`.

Сервер говорит по обычному HTTP только внутри сети Compose; порт 8080 наружу не открыт. Не открывайте его: пароли и заметки должны идти только по HTTPS.

## Добавить пользователя

```bash
docker compose exec amby-sync amby-sync-server user add alice
```

Команда выдаст **одноразовый код**, действует 24 часа. В приложении введите адрес сервера, имя пользователя и код, затем придумайте пароль. Приложение создаст ключи и покажет **код восстановления: сохраните его**. Если повторить `user add` для имени, у которого ещё нет пароля, выдастся новый код, а старый перестанет работать.

```bash
docker compose exec amby-sync amby-sync-server user list
docker compose exec amby-sync amby-sync-server user remove alice --yes   # удаляет все данные alice навсегда
```

Имя пользователя: от 1 до 64 символов из `a-z 0-9 . _ -`, начинается и заканчивается буквой или цифрой.

## Настройки (`.env`)

| Переменная                       | По умолчанию  | Что делает                                                   |
| -------------------------------- | ------------- | ------------------------------------------------------------ |
| `AMBY_SYNC_DOMAIN`               | обязательно   | ваше DNS-имя, без `https://`                                 |
| `AMBY_SYNC_VERSION`              | `latest`      | версия образа, см. [Закрепить версию](#закрепить-версию)     |
| `AMBY_SYNC_QUOTA_BYTES_PER_USER` | без ограничения | сколько зашифрованных байт может хранить один пользователь |

Остальные настройки сервера (срок хранения версий, лимиты загрузки и т. д.) перечислены в [README сервера](https://github.com/MrDarkOm/amby-notes/blob/main/sync/server/README.md#settings); при необходимости добавьте их в `environment:` сервиса `amby-sync` в `docker-compose.yml`.

## Резервная копия

Всё хранится в одном томе Docker. Так делается согласованная копия, пока сервер работает:

```bash
docker compose exec amby-sync amby-sync-server backup /data/backups/today
docker cp "$(docker compose ps -q amby-sync)":/data/backups/today ./amby-backup-today
docker compose exec amby-sync rm -r /data/backups/today
```

Копия (`amby-sync.db` и, если есть вложения, `blobs/`) так же нечитаема, как и живые данные. Храните её ещё и на другом компьютере и помните, что **на каждом устройстве тоже лежит полная копия ваших заметок**.

## Восстановление

Выполняйте в папке `sync`, копия лежит в `./amby-backup-today`:

```bash
docker compose down
docker compose run --rm --no-deps --entrypoint sh \
  -v "$PWD/amby-backup-today:/restore:ro" amby-sync -c \
  'rm -rf /data/amby-sync.db /data/amby-sync.db-wal /data/amby-sync.db-shm /data/blobs && cp -r /restore/. /data/'
docker compose up -d
```

Файлы `-wal` и `-shm` относятся к заменяемой базе, поэтому их нужно удалить. Восстановленный сервер старше того, что видели ваши устройства; они заметят, что сервер «откатился», и ничего не удалят, подстраиваясь под него.

## Обновление

Сначала сделайте резервную копию (см. выше), затем:

```bash
cd AmbyNotes-SelfHost && git pull     # заодно обновит и этот набор
cd sync
docker compose pull && docker compose up -d
```

База обновляется сама при первом запуске новой версии. Сервер не откроет базу, записанную более новой версией, поэтому для отката на старую версию нужна резервная копия.

## Закрепить версию

По умолчанию запускается `latest`. Чтобы обновляться только когда вы решите, впишите номер в `.env`:

```
AMBY_SYNC_VERSION=0.1.0
```

и выполните `docker compose up -d`. Доступные версии перечислены в разделе *Packages* на [странице репозитория](https://github.com/MrDarkOm/AmbyNotes-SelfHost). Caddy закреплён на старшей версии (`caddy:2`).

## Полезно знать

- `docker compose ps` показывает сервер как *healthy*, когда отвечает `/v1/info`. `docker compose logs amby-sync` показывает журнал; в нём никогда нет токенов, ключей, кодов подключения и тел запросов.
- Сервер со стёртыми данными получает новый случайный идентификатор, поэтому устройство, увидев его, останавливается, а не удаляет свои файлы под пустой сервер.
