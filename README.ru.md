# Amby Notes: свой сервер синхронизации

[English version](README.md)

Здесь всё, что нужно, чтобы запустить **сервер синхронизации** для [Amby Notes](https://github.com/MrDarkOm/amby-notes) на своём компьютере: файл Docker Compose с готовым образом, настройка Caddy, который сам получает HTTPS-сертификат, и эта инструкция. Кода сервера здесь нет: он лежит в [`amby-notes/sync/`](https://github.com/MrDarkOm/amby-notes/tree/dev/sync), а образ `ghcr.io/mrdarkom/ambynotes-sync` собирается из него.

## Что сервер видит и чего не видит

Ваши устройства шифруют всё до отправки. Сервер хранит заметки **в зашифрованном виде** и ничего не может прочитать: ключи до него не доходят. Он **не может прочитать**:

- текст заметок и вложений,
- названия файлов и папок и структуру папок,
- названия ваших устройств и хранилищ,
- ваш пароль, код восстановления и любой ключ.

Он **видит** (этого не скрыть): имена пользователей, сколько у вас файлов и примерно какого размера, когда они менялись, каким устройством, и с каких IP-адресов приходят запросы.

Раз сервер не может прочитать данные, он не может их и восстановить: если вы потеряете и пароль, и код восстановления, данные на сервере не вернёт никто. Файлы на ваших устройствах при этом остаются как были.

## Что нужно

- Компьютер с [Docker](https://docs.docker.com/engine/install/) и плагином Compose (`docker compose`).
- DNS-имя (например, `sync.example.org`), указывающее на этот компьютер.
- Открытые из интернета порты **80 и 443**: через них Caddy получает и продлевает HTTPS-сертификат.

## Быстрый старт

```bash
git clone https://github.com/MrDarkOm/AmbyNotes-SelfHost
cd AmbyNotes-SelfHost/sync
cp .env.example .env
```

Откройте `.env` и впишите в `AMBY_SYNC_DOMAIN` своё DNS-имя. Затем:

```bash
docker compose up -d
curl https://sync.example.org/v1/info    # должен ответить коротким JSON
```

В приложении укажите адрес сервера `https://sync.example.org`.

Сервер говорит по обычному HTTP только внутри сети Compose; порт 8080 наружу не открыт. Не открывайте его: пароли и заметки должны идти только по HTTPS.

## Аккаунты

По умолчанию войти могут только аккаунты, которые добавили вы:

```bash
docker compose exec amby-sync amby-sync-server user add alice
```

Команда печатает **одноразовый код**, он действует 24 часа. В приложении введите адрес сервера, имя пользователя и код, затем придумайте пароль. Приложение создаст ключи и покажет **код восстановления: сохраните его**. Повторный `user add` для имени, у которого ещё нет пароля, выдаёт новый код, а старый перестаёт действовать.

Чтобы люди могли зарегистрироваться сами, задайте в `.env` `AMBY_SYNC_OPEN_REGISTRATION=1`. Попытки ограничены по адресу, а `AMBY_SYNC_MAX_USERS` ограничивает число аккаунтов. Имена, занятые через `user add`, остаются за вами.

```bash
docker compose exec amby-sync amby-sync-server user list
docker compose exec amby-sync amby-sync-server user remove alice --yes   # удаляет всё у alice насовсем
```

Имя пользователя — от 1 до 64 символов из `a-z 0-9 . _ -`, начинается и кончается буквой или цифрой; заглавные буквы становятся строчными.

## Тарифы и подписки

Без файла тарифов синхронизировать может любой аккаунт, ограничивают его только настройки ниже. Файл тарифов задаёт именованные наборы пределов. Положите его в том данных как `/data/plans.json`:

```json
{
  "default_plan": "free",
  "plans": {
    "free": { "title": "Free", "sync": false },
    "notes": {
      "title": "Notes",
      "sync": true,
      "max_total_bytes": 1000000000,
      "max_file_bytes": 30416160,
      "max_history_bytes": 1000000000
    }
  }
}
```

- `sync: false` — тариф **без синхронизации**: аккаунт есть (вход, пароль, имена), данные, уже лежащие на сервере, можно скачать, вернуть и удалить, но новое не отправляется. Нет поля `sync` — значит `true`.
- Остальные пределы необязательны: `max_spaces`, `max_total_bytes` (текущие файлы и незавершённые загрузки), `max_file_bytes`, `history_days`, `max_history_bytes` (прежние версии; сверх него самые старые удаляются). Прежние версии в `max_total_bytes` не входят, поэтому задайте `max_history_bytes`, если сервером пользуются незнакомые вам люди.
- Новые аккаунты получают `default_plan`. Выдать аккаунту тариф, при желании с последним днём (включительно, по UTC), или снять его:

```bash
docker compose exec amby-sync amby-sync-server user plan set alice notes --until 2026-12-31
docker compose exec amby-sync amby-sync-server user plan set alice --default
docker compose exec amby-sync amby-sync-server user plan show alice
```

После последнего дня аккаунт сам возвращается на `default_plan`, ничего не удаляется. В приложении есть кнопка «Оформить подписку»; оплаты пока нет, кнопка подсказывает обратиться к вам.

Файл тарифов читается при запуске. Проверьте новый перед заменой: с испорченным файлом сервер не запустится.

```bash
docker compose cp plans.json amby-sync:/data/plans.new.json
docker compose exec amby-sync amby-sync-server plans check /data/plans.new.json
docker compose exec amby-sync mv /data/plans.new.json /data/plans.json
docker compose restart amby-sync
```

## Настройки (`.env`)

| Переменная                       | По умолчанию | Что значит                                                                         |
| -------------------------------- | ------------ | ---------------------------------------------------------------------------------- |
| `AMBY_SYNC_DOMAIN`               | обязательно  | ваше DNS-имя, без `https://`                                                       |
| `AMBY_SYNC_VERSION`              | `latest`     | какую версию образа запускать, см. [Закрепить версию](#закрепить-версию)           |
| `AMBY_SYNC_OPEN_REGISTRATION`    | `0`          | `1`: аккаунт можно создать из приложения без кода                                  |
| `AMBY_SYNC_MAX_USERS`            | без предела  | сколько аккаунтов может стать при открытой регистрации                             |
| `AMBY_SYNC_MAX_BLOB_BYTES`       | 512 МиБ      | наибольший зашифрованный файл; `30416160` соответствует пределу 30 МБ в приложении |
| `AMBY_SYNC_QUOTA_BYTES_PER_USER` | без предела  | сколько зашифрованных байт может хранить один пользователь (потолок над тарифами)  |
| `AMBY_SYNC_MIN_FREE_BYTES`       | 1 ГиБ        | запас свободного места; меньше — новые загрузки и аккаунты не принимаются          |
| `AMBY_SYNC_RETAIN_VERSION_DAYS`  | `30`         | сколько дней хранятся прежние и удалённые версии                                   |
| `AMBY_SYNC_MAX_LARGE_BODIES`     | `4`          | сколько запросов больше 1 МиБ читается одновременно; остальным «сервер занят»      |

В `.env.example` у каждой есть пояснение. Полный перечень, протокол и форматы — в [описании синхронизации v1](https://github.com/MrDarkOm/amby-notes/blob/dev/docs/sync-format.md) (на английском).

## Пределы, которые защищают сервер

- Если свободного места на диске меньше `AMBY_SYNC_MIN_FREE_BYTES`, сервер не принимает новые аккаунты, хранилища и загрузки; люди видят, что на сервере заканчивается место. Чтение, скачивание и удаление работают, чтобы место можно было освободить.
- Запросы входа — не больше 64 КиБ, и одновременно читается не больше `AMBY_SYNC_MAX_LARGE_BODIES` больших запросов: посторонний не забьёт память сервера.
- Неудачные входы ограничены по адресу и по имени. За Caddy из этого комплекта сервер берёт настоящий адрес из заголовка, который ставит Caddy (`AMBY_SYNC_TRUST_PROXY=1` в `docker-compose.yml`); никогда не открывайте порт 8080 наружу.

## Удаление данных

- **Из приложения**: человек может удалить серверную копию хранилища («Удалить с сервера…» в настройках синхронизации). Удаляется только копия на сервере и её прежние версии; файлы на всех устройствах остаются, а другие устройства сами перестают синхронизировать это хранилище.
- **Администратором**:

```bash
docker compose exec amby-sync amby-sync-server space list alice                 # номера и размеры, имена остаются зашифрованными
docker compose exec amby-sync amby-sync-server space remove alice <space_id> --yes
docker compose exec amby-sync amby-sync-server user remove alice --yes
```

Это нельзя отменить: сначала сделайте резервную копию.

## Резервная копия

Всё лежит в одном томе Docker. Так делается согласованная копия, пока сервер работает:

```bash
docker compose exec amby-sync amby-sync-server backup /data/backups/today
docker cp "$(docker compose ps -q amby-sync)":/data/backups/today ./amby-backup-today
docker compose exec amby-sync rm -r /data/backups/today
```

Копия (`amby-sync.db` и, если есть вложения, `blobs/`) так же нечитаема, как живые данные. Храните рядом `plans.json` и свой `.env`. Держите копию и на другом компьютере и помните: **на каждом устройстве тоже лежит полная копия его заметок**.

## Восстановление и откат

Выполните в папке `sync`, копия — в `./amby-backup-today`:

```bash
docker compose down
docker compose run --rm --no-deps --entrypoint sh \
  -v "$PWD/amby-backup-today:/restore:ro" amby-sync -c \
  'rm -rf /data/amby-sync.db /data/amby-sync.db-wal /data/amby-sync.db-shm /data/blobs && cp -r /restore/. /data/'
docker compose up -d
```

Файлы `-wal` и `-shm` относятся к заменяемой базе, поэтому их надо убрать. Восстановленный сервер старше того, что видели ваши устройства; они замечают, что он вернулся в прошлое, и ничего не удаляют ему в угоду.

Чтобы после обновления вернуться к прежней версии сервера, восстановите копию, сделанную перед обновлением, и закрепите прежнюю версию в `.env` (`AMBY_SYNC_VERSION`). Сервер не открывает базу, записанную более новой версией, поэтому один только старый образ не запустится. Когда новая версия меняет базу, она ещё и сама сохраняет копию прежней в `/data/backups/pre-v<N>-<время>.db`.

## Обновление

Сначала сделайте резервную копию (см. выше), затем:

```bash
cd AmbyNotes-SelfHost && git pull     # заодно обновляет этот комплект
cd sync
docker compose pull && docker compose up -d
docker compose ps                     # дождитесь «healthy»
```

База обновляется сама при первом запуске новой версии, сделав описанную выше копию. Всё описанное здесь (тарифы с `sync`, `--until`, пределы диска и запросов) требует сервер **0.2.0** или новее.

## Закрепить версию

По умолчанию запускается `latest`. Чтобы обновляться только когда решите сами, укажите номер в `.env`:

```
AMBY_SYNC_VERSION=0.2.0
```

и выполните `docker compose up -d`. Доступные версии — в разделе _Packages_ на [странице репозитория](https://github.com/MrDarkOm/AmbyNotes-SelfHost). Caddy закреплён на старшей версии (`caddy:2`).

## Полезно знать

- `docker compose ps` показывает сервер как _healthy_, когда отвечает `/v1/info`. `docker compose logs amby-sync` показывает журнал; в нём никогда нет токенов, ключей, кодов подключения и тел запросов.
- Сервер со стёртыми данными получает новый случайный идентификатор, поэтому устройство, увидев его, останавливается, а не удаляет свои файлы под пустой сервер.
